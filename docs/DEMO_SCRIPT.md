# ServicePilot AI · 3 分钟演示旁白稿

> 目标时长：180 秒；所有订单、客户和企业制度均为虚构数据。

## 0:00—0:12 · 开场

企业客服每天面对大量重复工单。ServicePilot AI 把分类、知识检索和系统操作放进一条可审计的本地工作流，同时为高风险问题保留人工控制。

## 0:12—0:44 · 自动分类与信息抽取

输入“不是物流问题，而是退款一直没到账”。普通关键词规则容易被前半句误导；优化后的引擎识别否定和转折，判断为退款退货、P2，并抽取订单号和金额。置信度、关键词和结构化字段都能被人工检查。

## 0:44—1:10 · RAG 与引用

系统不是直接让模型自由回答，而是先从企业知识库检索。回答旁边显示文档编号、章节、原文片段和制度来源。可选的本地模型只能改写已检索内容；引用超出允许列表就自动降级。

## 1:10—1:48 · 工单 API 工具

Agent 随后调用工单 API 创建记录。创建带幂等键，重复请求不会生成两张工单。队列支持查询和状态更新，更新必须携带版本号，避免两名客服互相覆盖。这里使用本地 SQLite 模拟企业工单系统，接口边界可以替换为真实 CRM。

## 1:48—2:25 · 自动转人工与评测

设备冒烟会被判断为 P0 安全问题，系统不会自动闭环，而是创建待人工工单。低置信度、隐私、支付欺诈、法律风险和知识缺口同样转人工。工具连续两次失败时也停止重试，并把完整工具轨迹交给人工。40 条固定评测覆盖常规、转折、敏感和失败场景。

## 2:25—2:40 · 错误到优化

Baseline 把“不是物流问题”误判为物流；加入语义方向权重后，分类改为退款退货，退款到账制度成为首要引用。优化前后由同一评测脚本自动生成。

## 2:40—2:54 · ROI 与架构

按一千张月工单的模拟假设，加权处理时长从八分钟降到约二点二分钟，每月节省约九十七小时、五千八百二十五元人工成本。数字可调，并明确不是生产承诺。

## 2:54—3:00 · 收尾

ServicePilot AI：让自动化有依据，让风险有出口，让价值可以被评测。
